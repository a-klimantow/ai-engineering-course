# Урок 8. `Review` в интерфейсе

Код урока лежит в `projects/feedback-inbox/`. Это начало сквозного проекта.

## Разминка

1. Что гарантирует схема в ответе модели, а что нет?
2. Какие три вещи даёт одна Zod-схема?

## Зачем

Службе поддержки приходят сотни отзывов. Читать все подряд долго. Если модель превращает каждый отзыв в объект `Review`, интерфейс может показать бейджи, вынести срочное наверх и дать фильтр по категории. Текст для этого не годится, нужен объект.

## Практика

Проект уже собран: страница с карточками, сервер, общая схема. Не хватает одного: функции `classify` на сервере.

### Шаг 1. Запусти и посмотри, как ломается

В двух терминалах:

```bash
npm run inbox:server
npm run inbox:web
```

Открой http://localhost:5174 и нажми «Разметить». Под каждой карточкой появится красное «Не получилось разметить», а в терминале сервера: `Error: classify ещё не написан`.

### Шаг 2. Напиши `classify` сам

Открой `projects/feedback-inbox/server.ts`, найди:

```ts
async function classify(text: string): Promise<Review> {
  // TODO (урок 8): вызови generateText и верни output
  throw new Error("classify ещё не написан")
}
```

Замени две строки внутри на вызов `generateText`. Всё нужное уже импортировано. Подсказки:

- образец лежит в `lessons/07-structured-output/extract-sdk.ts`, строки 18–24;
- модель: `ollama("qwen2.5:3b")`;
- system-промпт: константа `SYSTEM`;
- отзыв заверни в теги: `` `<review>${text}</review>` ``;
- в конце `return output`.

Перезапусти сервер (Ctrl+C, `npm run inbox:server`) и снова нажми «Разметить».

Ожидаемый результат: карточки по очереди получают бейджи, например `bug` `negative` и короткое описание под ними.

### Шаг 3. Найди ошибки модели глазами

Посмотри на карточки и ответь:

1. Есть ли 🔥 у отзыва про кнопку «Оплатить»?
