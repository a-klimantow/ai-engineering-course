# Урок 7. Структурированный вывод с Zod (конспект)

Задача: получать от модели не текст, а объект, с которым можно работать в коде.

- **Проблема урока 3**: «ровно одно слово» — это просьба, а не гарантия. Нужно больше полей, и парсить текст руками ненадёжно.
- **Zod-схема** — одно описание на три роли: подсказка для модели, проверка ответа, тип TypeScript (`z.infer`).
- **`generateText({ output: Output.object({ schema }) })`** → готовый объект в `result.output`.
- **`.describe()`** у поля — инструкция для модели прямо в схеме («суть в 3–7 словах»).
- **`z.enum`** вместо строки: модель может выбрать только из списка.
- **`supportsStructuredOutputs: true`** у провайдера: без него схема не уходит в Ollama, модель возвращает «какой-то JSON».
- **`NoObjectGeneratedError`**: ответ не JSON или не прошёл схему. В `error.text` — сырой ответ модели. Всегда обрабатывать.
- **Стриминг объекта**: `streamText` + `partialOutputStream` отдаёт объект по кусочкам — карточки появляются в UI, пока модель пишет. Поля могут быть `undefined`.
